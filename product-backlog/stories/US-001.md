## Story
Sebagai **pengembang galleon-fleet**, saya ingin **setiap CrewMember (Go: identitas organisasi
Squad/Ship/Role) terhubung secara struktural ke AliasedAgentConfig (Rust: model_provider/
skill_bundles/mcp_bundles)**, agar **eksekusi turn (ExecuteTurn gRPC) tahu persis config agent
mana yang dipakai, bukan mengandalkan konvensi penamaan manual yang bisa drift tanpa terdeteksi**.

## Konteks (Fakta Terverifikasi 2026-10-18)
- `CrewMember` (`engine/src/crew/dto.go`) hanya punya `ID/Name/Role/Status/Capabilities` — **tidak
  ada field yang merujuk ke Rust agent config**.
- `AliasedAgentConfig` (`crates/clawcrew-config/src/schema.rs:4068+`) adalah SSOT resolve
  `model_provider`/`skill_bundles`/`mcp_bundles`/`risk_profile`/`runtime_profile` — pola
  `config.agents.get(alias)` dipakai konsisten di 15+ lokasi Rust (delegate, channels, gateway,
  providers, a2a, SOP render).
- `ExecuteTurnRequest` (`proto/agent_service.proto:149`) hanya membawa `session_id`, `model`
  (string polos, sudah di-resolve Go SEBELUM dikirim), `messages`, `tools` — **tidak ada
  `agent_id`/`crew_member_id`/`agent_alias`**.
- `SopStep.agent: Option<String>` (`crates/clawcrew-runtime/src/sop/types.rs:369`) di titik
  eksekusi (`sop/mod.rs:1200`) HANYA dirender jadi teks bullet markdown untuk prompt — tidak
  pernah di-resolve lewat `config.agents.get()` seperti pola 15+ lokasi lain.
- **Kesimpulan**: dua sistem identitas (Go organisasi, Rust eksekusi) hidup sendiri-sendiri,
  dihubungkan HANYA oleh konvensi penamaan manual (orang menyamakan string "backend" di kedua
  sisi), bukan referensi struktural. Ini DIVERIFIKASI [V] langsung dari kode, bukan asumsi.

## Kriteria Penerimaan (Acceptance Criteria)
- [ ] Diberikan satu `CrewMember` dengan field `AgentAlias` terisi, ketika Go memanggil
      `ExecuteTurn`, maka Rust menerima alias itu dan bisa resolve `AliasedAgentConfig` yang
      sesuai (bukan hanya `model` string polos)
- [ ] Diberikan `SopStep.agent` terisi, ketika step itu dieksekusi, maka sistem me-resolve
      `config.agents.get(step.agent)` (konsisten dengan 15+ lokasi lain), bukan hanya merender
      jadi teks prompt
- [ ] Diberikan `CrewMember.AgentAlias` menunjuk alias yang TIDAK ADA di `config.agents`, maka
      sistem gagal jelas (fail loud) saat validasi config — bukan silent fallback ke default

## Cek INVEST
- **Independent**: ya — tidak depend ke multi-runtime CLI orchestrator (sudah di-scope-out)
- **Negotiable**: ya — mekanisme jembatan (field baru vs lookup table) masih bisa didiskusikan di SPEC
- **Valuable**: ya — ini blocking SEMUA fitur yang butuh tahu "CrewMember mana jalankan dengan config apa", termasuk SOP RACI/constraint yang sudah didesain tapi belum bisa ditegakkan tanpa jembatan ini
- **Estimable**: ya — perubahan proto + 1 field Go + wiring resolve di titik SOP, scope jelas dari audit
- **Small**: ya — HANYA jembatan identitas, TIDAK termasuk redesain Quest/RACI/multi-runtime (itu story lain)
- **Testable**: ya — 3 acceptance criteria di atas semuanya bisa diuji dengan test konkret (unit test Rust + Go)
