## Story
Sebagai **Developer Backend Galleon**, saya ingin **memecah file-file modul gateway yang berukuran raksasa (>2000 baris) menjadi submodule yang kohesif**, agar **struktur kode mudah dipelihara, waktu review PR singkat, dan batas kepemilikan kode jelas tanpa regresi API**.

## Kriteria Penerimaan (Acceptance Criteria)
- [ ] Diberikan file `api_config.rs` (4.940 baris), ketika diekstrak menggunakan pola SAFE RF-A (submodule `api_config/`), maka tidak ada file individual >2.000 baris dan `tests` terpisah di `tests.rs`.
- [ ] Diberikan file `ws.rs` (4.259 baris), ketika diekstrak ke submodule `ws/`, maka transport, session/actor handler, dan unit test terisolasi secara bersih.
- [ ] Diberikan file `api_sections.rs` (2.413 baris), ketika diekstrak ke submodule `api_sections/`, maka logika per-section dan schema handler terpisah rapi di bawah 2.000 baris.
- [ ] Diberikan seluruh public re-export (`pub use`) tetap dipertahankan, ketika `cargo check -p clawcrew-gateway` dan `cargo nextest run -p clawcrew-gateway --locked` dijalankan, maka seluruh test lulus 100% tanpa breaking changes pada rute Axum gateway.

## Cek INVEST
- **Independent**: Dapat dikerjakan per modul (`api_config`, `ws`, `api_sections`) secara berurutan tanpa memblokir sistem lain.
- **Negotiable**: Batas submodule dapat disesuaikan per concern.
- **Valuable**: Mengeliminasi technical debt kritis pasca-T3-02 gateway decoupling.
- **Estimable**: Estimasi ukuran dan waktu ukur konkret (<1 jam per sub-task).
- **Small**: Dipecah menjadi sub-task terfokus per-modul.
- **Testable**: Diverifikasi langsung via test suite gateway (100% pass).
