## Deskripsi
Di `crates/clawcrew-gateway/src/strangler_runner.rs`, loop penerima stream `ExecuteTurn` memperlakukan DUA kondisi berbeda secara identik: event protokol `TurnCompleted` (baris ~309, `break`) dan `Ok(None)` yakni stream gRPC ditutup oleh peer/transport tanpa event terminal apa pun (baris ~324, juga `break`). Keduanya jatuh ke kode yang sama setelah loop (baris 351) yang SELALU mengembalikan `Ok(AgentTurnSuccess { .. })`. Tidak ada percabangan yang membedakan "AgentEngine benar-benar menyelesaikan turn" dari "koneksi putus/stream ditutup prematur (network blip, crash Go, timeout)".

Akibat: panggilan caller `/api/turn` -> `run_turn` bisa menerima `AgentTurnSuccess` padahal turn belum benar-benar selesai menurut kontrak AgentEngine. Ini false success di jalur produksi utama chat.

## Definition of Done (DoD)
- [ ] Loop pembaca stream membedakan `TurnCompleted` (jalur sukses sah) dari `Ok(None)` (EOF tanpa event terminal) -- hanya `TurnCompleted` yang boleh menghasilkan `AgentTurnSuccess`.
- [ ] `Ok(None)` sebelum `TurnCompleted` menghasilkan `AgentTurnError` yang membawa `committed_response` (partial output dipertahankan, TIDAK dibuang) dan pesan error yang jelas membedakan dari error gRPC biasa.
- [ ] Jalur `Error` event dan jalur `Err(status)` (gRPC transport error) tetap berperilaku sama seperti sekarang (tidak diubah) -- hanya `Ok(None)` yang berubah perilaku.
- [ ] Test baru (unit/integration di `strangler_runner.rs` atau test terdekat) yang: (a) mensimulasikan stream berhenti tanpa `TurnCompleted` -> assert hasil BUKAN `AgentTurnSuccess`; (b) mensimulasikan stream normal dengan `TurnCompleted` -> assert hasil TETAP `AgentTurnSuccess` seperti sebelumnya (no regression).
- [ ] `cargo check --workspace` dan `cargo nextest run -p clawcrew-gateway --locked` lulus 100%.
- [ ] PR dibuka ke branch `testing`, CI dev-ci hijau (`local/Required Gate` pass).
