## Ringkasan (Summary)
Pekerjaan investigasi kepemilikan riwayat percakapan (history ownership) dan propagasi `context_window` dari Rust Gateway ke Go Agent Engine pada [`strangler_runner.rs`](file:///home/diezy/Apps/galleon-fleet/crates/clawcrew-gateway/src/strangler_runner.rs) telah selesai 100%. Berdasarkan audit primer terhadap kode Go (`engine/`), Go `Orchestrator` didesain stateless terhadap riwayat multi-turn dan bergantung pada `TurnRequest.context_window` yang diparsing oleh Go `ContextResolver` (PR #84). Oleh karena itu, arsitektur yang dipilih adalah **Inline Gateway History Propagation** (Jalur 2). Riwayat percakapan `self.history` pada gateway kini diserialisasikan ke JSON `ContextWindowPayload` dengan batas truncation sliding window 50 pesan terakhir (`DEFAULT_MAX_HISTORY_MESSAGES`), diverifikasi dengan tes multi-turn bebas duplikasi prompt, dan PR #87 telah dibuka ke branch `testing`.

## Yang Dikerjakan (What Was Done)

### 1. Investigasi Kode Sumber & Penentuan History Owner (SSOT)
Investigasi mendalam dilakukan pada tiga titik codebase Go `engine/`:
- [`engine/app/wire_gen.go`](file:///home/diezy/Apps/galleon-fleet/engine/app/wire_gen.go#L36-L40): Inisialisasi dependency injection menunjukkan `crew.NewService` hanya menerima dependensi eksternal (LLM client, tool registry, session manager), tanpa session store percakapan berbasis SQLite untuk turn history.
- [`engine/src/crew/services.go`](file:///home/diezy/Apps/galleon-fleet/engine/src/crew/services.go#L20-L120): `Orchestrator` menangani request per turn secara stateless (`ExecuteTurn`). Layanan membaca `req.ContextWindow` dan mendelegasikannya ke `contextResolver.ResolveContext(ctx, req.Prompt, req.ContextWindow)`.
- [`engine/pkg/store/sqlite/`](file:///home/diezy/Apps/galleon-fleet/engine/pkg/store/sqlite/schema.go): Skema SQLite hanya menyimpan metadata job/workflow dan audit trail, tidak mengelola durable transcript multi-turn turn-level untuk AgentEngine.
- **Keputusan Arsitektur**: Rust Gateway bertindak sebagai **Single Source of Truth (SSOT)** riwayat percakapan sesi (`self.history`). Gateway memproyeksikan riwayat ini ke `context_window: Vec<u8>` dalam bentuk JSON wire DTO yang didekode oleh Go `DefaultContextResolver` (`ContextWindowPayload`).

### 2. Implementasi Serialisasi & Propagasi Konteks pada Gateway
Pada [`crates/clawcrew-gateway/src/strangler_runner.rs`](file:///home/diezy/Apps/galleon-fleet/crates/clawcrew-gateway/src/strangler_runner.rs):
- **Model Wire DTO**: Menambahkan struct `ContextWindowPayload` dan `ContextChatMessage` (`role`, `content`) yang kompatibel penuh dengan kontrak serialisasi Go di `engine/domain/crew/context.go`.
- **Kebijakan Truncation (Sliding Window)**: Ditetapkan `const DEFAULT_MAX_HISTORY_MESSAGES: usize = 50`. Nilai ini menjaga agar payload gRPC/IPC tetap ringkas, menghindari beban deserialisasi berlebih, sementara Go `ContextResolver` mengontrol anggaran token sliding window (8.192 token).
- **Fungsi Serialisasi**: Dibuat helper `serialize_context_window(history: &[ConversationMessage], max_messages: usize) -> Vec<u8>`. Jika riwayat kosong, mengembalikan `Vec::new()`.
- **Tiga Titik Pembentukan Request**:
  1. `process_message`: Diisi `serialize_context_window(&[], DEFAULT_MAX_HISTORY_MESSAGES)` dengan dokumentasi jelas bahwa helper ini memproses single message stateless.
  2. `turn_streamed_with_steering_state`: Diisi `serialize_context_window(&self.history, DEFAULT_MAX_HISTORY_MESSAGES)` untuk meneruskan riwayat turn sebelumnya pada agent session aktif.
  3. `test_handle_api_turn_sse`: Diisi sample context window valid untuk pengujian API SSE handler.

### 3. Pencegahan Duplikasi Riwayat dan Prompt
- Sesuai kontrak Go `ContextResolver`, Go menggabungkan pesan riwayat dari `context_window` lalu menambahkan `req.Prompt` sebagai pesan pengguna paling mutakhir.
- Gateway memproyeksikan `self.history` (yang baru mencakup turn 1 s.d. N-1) ke dalam `context_window`, dan meletakkan input turn N hanya pada `req.prompt`.
- Mekanisme ini menjamin tidak terjadi prompt ganda atau duplikasi riwayat di pipeline model.

### 4. Pengujian Otomatis (Testing)
- **Integration Test Multi-Turn (Rust)**: Menambahkan `test_strangler_agent_session_multi_turn_context_propagation` di `strangler_runner.rs` menggunakan mock engine gRPC yang merekam `TurnRequest`. Membuktikan turn 1 mengirim context window kosong, turn 2 membawa riwayat turn 1 (user prompt + assistant reply), dan tidak ada duplikasi pesan.
- **Unit Test Truncation (Rust)**: Menambahkan `test_serialize_context_window_truncation` (memastikan 60 pesan dipotong menjadi 50 pesan terbaru) dan `test_serialize_context_window_empty_returns_empty_vec`.
- **Contract Test Antar-Bahasa (Go)**: Menambahkan `TestContextResolver_GatewaySerializedContextWindowContract` di `engine/domain/crew/turn_test.go` untuk memvalidasi bahwa output biner JSON dari Rust didekode secara presisi oleh Go `ContextResolver`.
